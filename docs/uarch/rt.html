Carolyne Rename Table

One register class, one map. Two banks of clocked state with a chain of single-cycle wires strung between them — and four events competing to write it.

The four stores

Every one is an RtEntry Karray — a record of renamed (1 bit) and prf_idx (ceil_log2(amt_prf) bits), one entry per architectural register. What separates them is the backing: a reg survives the clock edge, a wire does not.

reg master_rt (1, amount)

The live map at the cycle boundary — where each architectural register lives right now.

reg spec_rt (sptag_len, amount)

One checkpoint per speculation tag, so a mispredict can put the map back.

wire temp_commit (1, amount)

The map with this cycle's retirements taken out of it.

wire temp_dispatch (rename_ports, amount)

One row per rename lane — the map as it stands after that lane has written it.

One cycle

The map leaves master_rt, is copied forward through the wire rows one lane at a time, and is clocked back in at the edge. Each hop is a plain copy; the events overlay single entries on top of it at a higher priority.

  • clocked — survives the edge
  • combinational — this cycle only

Speculation

A branch takes a copy of the whole map under its one-hot tag. When that branch turns out to be wrong, the copy goes back.

Which write wins

Kathryn emits a component's update events in ascending priority inside one always block, so the last one written is the one that takes effect. The ladder below is that emission order, top to bottom.

10
copy_row — the chain

Default user priority. Each row copied forward from the one before it.

13
PRI_COMMIT — on_commit

A retired physical register stops being named, in the live map and in every checkpoint.

14
PRI_RENAME — on_rename

A lane writes its destination, and a branch checkpoints the row it leaves behind.

15
PRI_MIS_PRED — on_mis_pred wins

The checkpoint goes back into the map, over the top of everything above.

Entry points

One method is automatic; the rest are called by whoever wires the stage.

MethodWhenWhat it does
on_normal_flow every cycle, automatically Marked @flow, so Kathryn builds it. Lays down the copy chain and the clocked writeback.
book_rename per lane, at rename Records the lane's request, destination and tag into rename_metas[port_idx].
on_rename once, after every lane is booked Turns the booked lanes into hardware: the entry writes, and the checkpoint on a branch.
on_commit at retirement Where the map still names the retiring physical register, it stops naming it.
on_mis_pred on a wrong branch Copies the checkpoint the one-hot tag selects back into master_rt.

Three helpers, three Karray rules

Each of these exists because of a constraint in Kathryn's Karray, not because of anything about renaming. They spell an intent Kathryn has no direct statement for.

copy_row()

A selection collapses every dimension to one element — there are no ranges, so a whole-row copy is a loop of element copies.

write_entry()

A runtime-indexed write needs a reg backing, because a wire cannot hold its non-selected elements. On a wire the index moves into the guard instead — same hardware.

OH()

A callable index splits by direction: per-index enable on a write, 2:1 reduce select on a read. One object covers both by dispatching on its argument count.

Not yet resolved

Four row-index choices stop elaboration. With all four bypassed in a scratch copy the module builds, so nothing else is outstanding.

  1. on_normal_flow The forward-copy loop runs to sptag_len, but temp_dispatch has rename_ports rows.
  2. on_normal_flow The writeback reads temp_commit[sptag_len−1], and temp_commit has one row.
  3. on_rename temp_dispatch[rename_port_idx−1] is index −1 on lane 0, and it runs in addition to the if rename_port_idx == 0 branch rather than instead of it.
  4. on_rename The entry write targets temp_commit[rename_port_idx], which has one row, so lane 1 is out of bounds.
